1. Connection

The browser builds the WebSocket URL from the current host. Use wss: on HTTPS and ws: on HTTP.

const proto = location.protocol === "https:" ? "wss:" : "ws:";
const socket = new WebSocket(proto + "//" + location.host + "/ws/transcribe");
socket.binaryType = "arraybuffer";

2. Client → Server messages

Control messages are sent as JSON text frames. Audio is sent as a binary frame.

{ "type": "start", "domain": "medical" } // optional domain profile
{ "type": "stop" }    // stop server-side recorder/session
{ "type": "clear" }   // clear transcript on server/client
{ "type": "ping" }    // latency check, server replies with pong

3. Binary audio packet format

Each audio frame keeps the current mechanism: 4-byte little-endian metadata length, then UTF-8 JSON metadata, then PCM audio bytes.

[uint32 metadataLength LE][metadata JSON UTF-8][pcm_s16le audio]

metadata = {
  sampleRate: audioContext.sampleRate,
  channels: 1,
  format: "pcm_s16le",
  frames: pcm.length,
  sentAt: performance.now()
}

4. Browser audio capture config

The current client captures mono microphone audio and sends approximately 40 ms chunks after converting Float32 samples into signed 16-bit PCM.

navigator.mediaDevices.getUserMedia({
  audio: {
    echoCancellation: true,
    noiseSuppression: true,
    autoGainControl: true,
    channelCount: 1
  }
});

5. Server → Client message types

The UI handles these existing server message types without changing their meaning.

hello      -> contains clientId and optional settings
ready      -> recorder/session ready, optional settings
status     -> queueDepth and state
realtime   -> interim transcript update
final      -> final transcript segment
timeline   -> recorder/wake/transcription event
clear      -> clear local transcript
warning    -> non-fatal warning
error      -> error message
pong       -> latency response

6. Integration checklist for any platform

  • Open WebSocket at /ws/transcribe.
  • Send {"type":"start","domain":"medical"} before audio packets when using a domain profile.
  • Capture mono audio and convert it to pcm_s16le.
  • Send packets using the exact metadata-length + metadata + PCM layout.
  • Handle realtime for interim text and final for confirmed text.
  • Send {"type":"stop"} when recording ends.
